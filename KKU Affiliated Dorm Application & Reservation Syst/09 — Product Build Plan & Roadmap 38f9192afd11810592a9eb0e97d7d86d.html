Purpose

This page turns the current live-product direction into a buildable core product release plan for the KKU Affiliated Dorm Application & Reservation System.

It has been cleaned to remove older Next.js/Node.js/Vercel-style prototype notes. The current stack is Nuxt + Go chi + PostgreSQL + GORM/sqlc + SeaweedFS + Nginx + Docker Compose.

Final implementation stack

Frontend: Nuxt + shadcn-vue + Tailwind CSS
Backend: Go + chi
Database access: GORM + sqlc
Database: PostgreSQL
File/object storage: SeaweedFS
Reverse proxy: Nginx
Runtime/deployment: Docker / Docker Compose
CI/CD: No GitHub Actions for current delivery plan

Updated core product release objective

Build a working or clickable prototype that proves:

  1. Dorm managers can open affiliated dorm application campaigns.
  1. Applicants can apply online instead of using only paper/manual contact.
  1. Payment requirements are shown clearly before submission.
  1. Applicants can upload payment slips.
  1. Staff can verify or reject slips.
  1. Approved applications become reservations.
  1. Remaining room/room-type availability updates.
  1. Admin can export/report approved reservations and verified payments.

Product principle

Do not overbuild integrations first.

The core product release should still be useful even if:

  • KKU SSO is not integrated yet.
  • Real payment gateway is not integrated yet.
  • Existing invoice system is not directly integrated yet.
  • Exact room assignment is not included yet.
  • GitHub Actions is not used yet.

Build workflow without GitHub Actions

Use simple scripts or Makefile commands first.

Recommended commands:

make dev
make test
make build
make migrate-up
make migrate-down
make deploy

GitHub Actions is intentionally excluded from core product release. Add CI/CD later only after repository structure, deployment target, and testing strategy are stable.

What to avoid in first build

Avoid these until rules are confirmed:

  • Automatic payment confirmation
  • Real payment gateway
  • Exact room selection
  • Complex allocation algorithm
  • Auto-refund
  • Deep invoice integration
  • Multi-dorm launch all at once
  • Kubernetes
  • Kafka
  • Microservices
  • GitHub Actions

Final core product release statement for stakeholders

For the first version, we recommend building an online application and reservation management workflow for one or more affiliated dorms. The system will not replace the official invoice/payment system immediately. Instead, it will collect applicant data, show payment conditions, receive payment slips, support staff verification, confirm reservations, track room availability, store files securely in SeaweedFS, and export approved data for the existing official process.
