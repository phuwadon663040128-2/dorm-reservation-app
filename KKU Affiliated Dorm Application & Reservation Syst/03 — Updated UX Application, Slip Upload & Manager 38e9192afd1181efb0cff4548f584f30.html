03 — Updated UX: Application, Slip Upload & Manager Dashboard

UniPay UX update

Show the UniPay step and status in the applicant flow when available. Manual evidence upload is fallback only. See page 12.

Purpose

This page defines the current UX direction for the KKU Affiliated Dorm Application & Reservation System.

It replaces the older allocation-status UX. The current UX focus is application campaigns, payment condition clarity, slip upload, staff verification, reservation status, and dorm manager operations.

Main UX promise

Applicants should be able to answer these quickly:

  • Which affiliated dorms are open now?
  • What room types are available?
  • What do I need to pay before my reservation is confirmed?
  • Did I submit my application correctly?
  • Did I upload my payment slip correctly?
  • Is my slip verified?
  • Is my reservation confirmed?
  • What do I do next?

Dorm managers should be able to answer:

  • How many applicants submitted today?
  • How many uploaded slips?
  • How many slips are waiting for verification?
  • How many reservations are confirmed?
  • How many rooms/room types remain?
  • Which applicants need follow-up?
  • Which data should be exported to the official invoice/payment workflow?

Applicant flow — public application

Applicant opens public campaign
→ views dorm and room type details
→ sees price and payment condition
→ fills online application
→ uploads document/payment slip
→ submits
→ waits for staff verification
→ receives approved/reserved, rejected, expired, or waitlist status

Applicant flow — current resident renewal

Current resident opens renewal campaign
→ confirms personal/room information
→ chooses stayต่อ / not stayต่อ
→ sees payment requirement
→ uploads slip if required
→ staff verifies
→ reservation confirmed
→ room is removed from public availability

If renewal is not core product release, admin enters remaining room type quota manually after external renewal process.

Admin flow — slip verification

Admin opens slip verification queue
→ filters unverified slips
→ opens applicant detail
→ checks slip/payment info
→ approves, rejects, or asks for re-upload
→ system updates reservation status
→ applicant sees update

Must-design applicant screens

1. Campaign landing page

Purpose:

  • Show currently open affiliated dorm campaigns.

Content:

  • Campaign name
  • Dorm name
  • Who can apply
  • Application open/close date
  • Room type availability summary
  • Payment requirement summary
  • Apply button

Important UX:

  • Payment condition must be visible before applying.
  • Closed/full campaigns must be clearly marked.

2. Dorm/room type detail page

Purpose:

  • Help applicant decide before applying.

Content:

  • Dorm name
  • Room type
  • Capacity
  • Price
  • Damage deposit
  • Required upfront payment
  • Remaining quota or availability status
  • Facilities
  • Rules
  • Required documents
  • Payment deadline
  • Contact info

3. Online application form

Purpose:

  • Replace paper form as much as possible.

Sections:

  • Applicant information
  • Student information
  • Applicant type
  • Desired dorm/room type
  • Contact information
  • Emergency contact
  • Document upload if needed
  • Agreement checkbox

Applicant type examples:

  • Current resident renewing
  • Senior student from another dorm
  • New first-year student
  • International student
  • General applicant

4. Payment instruction page

Purpose:

  • Make payment requirement impossible to misunderstand.

Show:

  • Required amount
  • What the payment is for
  • Payment deadline
  • Bank/account/payment channel placeholder
  • Slip upload button
  • Warning that reservation is not confirmed until verified

Thai copy:

การจองยังไม่สมบูรณ์ กรุณาอัปโหลดหลักฐานการชำระเงินและรอเจ้าหน้าที่ตรวจสอบ

English copy:

Your reservation is not confirmed yet. Please upload your payment slip and wait for staff verification.

5. Slip upload screen

Fields:

  • Payment type
  • Amount paid
  • Payment date/time
  • Slip image/file upload
  • Optional note

Validation:

  • File required
  • Amount required
  • Date/time required
  • Allowed file type only
  • Maximum file size shown before upload

6. Reservation status tracker

Statuses:

  • Application submitted
  • Waiting for payment
  • Slip uploaded
  • Staff verifying
  • Need re-upload
  • Reserved / approved
  • Rejected
  • Cancelled
  • Expired

Recommended tracker:

Submitted → Slip Uploaded → Staff Verifying → Reserved

Rejected slip tracker:

Submitted → Slip Uploaded → Need Re-upload → Staff Verifying → Reserved

7. Approved reservation screen

Show:

  • Reservation confirmed
  • Dorm/room type
  • Applicant name
  • Payment verified date
  • Next steps
  • Contact info
  • Download/print confirmation placeholder

8. Rejected or re-upload screen

Show:

  • Reason for rejection
  • What to fix
  • Deadline to re-upload
  • Re-upload button
  • Contact dorm staff

UX principle

The key UX is no longer “students wait for fair allocation result.”

The key UX is:

Applicants must clearly understand payment requirements and reservation status, while dorm managers must quickly verify slips and control room availability.
