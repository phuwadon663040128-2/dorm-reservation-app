# การออกแบบตึก 3D สำหรับหน้าเลือกห้องพัก

> วิเคราะห์แนวทางสร้างอาคาร 3D บนเว็บ (วรเรสซิเดนซ์ 8 อาคาร + วรอินเตอร์ 4 อาคาร)
> Flow เป้าหมาย: เลือกหอ → เห็นตึก 3D → กดชั้นบนตึก → animation ซูมเข้าชั้น → แสดงแผนผังห้อง (overlay ที่ทำไว้แล้ว)

## 1. สิ่งที่รู้จากข้อมูลจริง

- **รูปทรงตึก:** ทุกตึกเป็นรูปตัว L (ยืนยันจากภาพดาวเทียม + แบบแปลน) — ปีกหลักแนวนอน ~470×180 หน่วย + ปีกตั้งฉาก ~154×230 หน่วย (สัดส่วนวัดจาก planOverlays ที่ปรับเทียบแล้ว)
- **จำนวนชั้น:** วรเรสซิเดนซ์ 4 ชั้น/ตึก · วรอินเตอร์ 7 ชั้น/ตึก
- **การจัดวาง (ดาวเทียม):** หอ 8 หลัง = ตึก L จับคู่หันหน้าเข้าหากัน 4 คู่ ล้อมสำนักงาน+โรงอาหารตรงกลาง · วรอินเตอร์ = 4 ตึก (A–D) จับคู่ 2 คู่ตาม KEYPLAN ในแบบแปลน (D บนซ้าย, C ล่างกลาง, B ล่างขวา, A บนขวา)
- ⚠️ ตำแหน่งเลขตึก 1–8 บนแผนที่จริงยังไม่มีข้อมูลยืนยัน — ทำเป็นข้อมูล config แก้ทีหลังได้

## 2. เปรียบเทียบ 3 แนวทาง

| เกณฑ์ | ① CSS 3D (แนะนำ) | ② Three.js (WebGL) | ③ SVG Isometric |
|---|---|---|---|
| น้ำหนักที่เพิ่มใน bundle | **0 KB** (ใช้ CSS transform ล้วน) | ~150 KB gzip + โค้ด scene | 0 KB |
| กดเลือก "รายชั้น" บนตึก | ง่ายมาก — ชั้น = `<button>` จริง (เข้าถึงได้, focus ได้, aria ครบ) | ต้องทำ raycasting เอง + DOM overlay สำหรับ label | ง่าย (path ต่อชั้น) |
| Animation ซูมเข้าชั้น → กลายเป็นแผนผัง | **ทำได้สวยเป็นธรรมชาติ**: หมุนกล้องเป็น top-down + scale + crossfade เข้าแผนจริง ด้วย CSS transition ตัวเดียว | ทำได้สวยสุด (กล้องจริง) แต่โค้ดเยอะ ต้องใช้ tween | ทำได้แค่ scale+crossfade (มุมมองตายตัว) |
| หมุนดูรอบตึก (orbit) | จำกัด (หมุนแกนเดียวได้) | ✓ อิสระเต็มที่ | ✗ |
| แสง/เงาสมจริง | จำลองด้วยความสว่างรายหน้า (พอสวย) | ✓ จริง | จำลองด้วย gradient |
| ธีมสว่าง/มืดของเว็บ | **อัตโนมัติ** (ใช้ตัวแปรสี Tailwind เดิม) | ต้อง sync สี canvas เอง | อัตโนมัติ |
| มือถือ | ✓ GPU-accelerated ลื่น | ✓ แต่กินแบต/เครื่องร้อนกว่า | ✓ เบาสุด |
| ความเสี่ยง/การดูแลต่อ | ต่ำ — เป็น Vue component ธรรมดา | สูงกว่า (dependency + API เฉพาะทาง) | ต่ำ |
| แรงงานโดยประมาณ | ~1–1.5 วัน | ~2–3 วัน | ~1 วัน |

### ✅ คำแนะนำ: แนวทาง ① CSS 3D

เหตุผลหลัก: flow ที่ต้องการ (โชว์ตึก → กดชั้น → ซูมดิ่งลงไปเป็นแผนผัง) **ไม่ต้องการ orbit อิสระ** ซึ่งเป็นข้อได้เปรียบเดียวที่มีน้ำหนักของ Three.js — CSS 3D ให้ครบทุกอย่างที่เหลือ: ชั้นเป็นปุ่มจริงกดง่าย, ธีมตามเว็บอัตโนมัติ, ไม่เพิ่ม dependency, และ animation "หมุนกล้องเป็นมุมบน + ซูม + ละลายเข้าแผนผังจริง" ทำด้วย transition เดียวได้เนียนพอดีกับ use case · ถ้าวันหน้าอยากได้ orbit จริงค่อยยกไป Three.js ได้เพราะข้อมูล config ใช้ร่วมกัน

## 3. สถาปัตยกรรมที่เสนอ

```
src/lib/campus3d.ts        ← ข้อมูลตึกเป็น config ล้วน (เพิ่ม/แก้ไม่แตะ component)
  dormGroupId → buildings[]:
    { code, label, floors, position {x,z}, rotationY (0/90/180/270 สำหรับ L ประกบกัน),
      footprint: { main: {w,d}, wing: {w,d, corner} } }

src/components/domain/Campus3D.vue    ← ฉาก: ground + ตึกทุกหลัง + เข็มทิศ + label
src/components/domain/Building3D.vue  ← ตึก 1 หลัง: ชั้น = slab รูปตัว L ซ้อนกัน (กล่อง 2 ใบ/ชั้น × 5 หน้า)
```

**การผูกเข้ากับ RoomBrowser (ของเดิมไม่พัง):**
- เพิ่มปุ่มมุมมองที่สาม: `ตึก 3D | ผังตึก | รายการ`
- สถานะ: เลือกหอ → Campus3D แสดงตึกทั้งหอ (ตึกที่มีข้อมูลห้องเปิดสว่าง, ที่ยังไม่มีข้อมูลหรี่ + ป้าย "ยังไม่เปิดข้อมูล")
- กดตึก → กล้องเลื่อน/ซูมเข้าตึกนั้น ตึกอื่นจางลง → slab แต่ละชั้นโชว์ "ชั้น N · ว่าง X ห้อง"
- กดชั้น → ลำดับ animation (ข้อ 4) → จบด้วยการตั้ง `selectedBuilding + selectedFloor` แล้วสลับไปมุมมองแผนผังเดิม (RealPlanOverlay/FloorPlanGrid) → มีปุ่ม "← กลับมุมมองตึก 3D"

## 4. สเปก Animation "ซูมเข้าชั้น" (CSS transition ทั้งหมด)

1. **Campus view** — ฉากเอียง isometric (`rotateX(~55°) rotateZ(±45°)`), ตึกมีเงาอ่อน, hover ตึก = ยกขึ้น 6px + ขอบ primary
2. **กดตึก** (400ms ease-out) — scene translate+scale ให้ตึกอยู่กลางจอ, ตึกอื่น opacity 25%
3. **Building view** — hover ชั้น = slab เลื่อนแยกขึ้นเล็กน้อย (exploded hint) + tooltip จำนวนห้องว่าง
4. **กดชั้น** (700ms) — ชั้นที่อยู่เหนือเลื่อนขึ้น+จางหาย → กล้องหมุน `rotateX → 90°` (มุมมองจากบนตรง ๆ) พร้อม scale เข้า slab ที่เลือก → หน้า top ของ slab crossfade เป็นภาพแผนผังจริง → สลับ component เป็นแผนผังห้องแบบ interactive
5. **ย้อนกลับ** — เล่นลำดับถอยหลัง (state เก็บใน RoomBrowser จึงกลับมาที่ตึก/ชั้นเดิมถูก)
6. เคารพ `prefers-reduced-motion`: ข้าม animation → ตัดเข้าแผนผังทันที

## 5. โทนสี (จากธีมเว็บ)

- ตัวตึก: `bg-card` + หน้าอาคารไล่ความสว่าง 3 ระดับ (หน้า/ข้าง/หลังคา) จากตัวแปรธีม — โหมดมืดได้เอง
- ชั้นที่ hover/เลือก: `primary` (ส้มอิฐ KKU) · ชั้นไม่มีข้อมูล: `muted`
- ป้ายว่าง/จองชั่วคราว: จุดสี emerald/amber ตามภาษาสีเดิมของระบบ
- พื้นสนาม: `muted/30` + เส้นกริดจาง + เข็มทิศเดิมจาก RealPlanOverlay

## 6. ขั้นตอนลงมือ (เมื่อยืนยันแนวทาง)

1. `campus3d.ts` — config ตึก 12 หลัง (ตำแหน่ง/มุมหมุนอิงภาพดาวเทียม, เลขตึกทำเป็นค่าแก้ได้)
2. `Building3D.vue` — L-slab ต่อชั้น + สถานะ hover/disabled
3. `Campus3D.vue` — ฉาก, กล้อง 3 สถานะ (campus/building/dive), เข็มทิศ, label
4. ผูกเข้า RoomBrowser + ปุ่มมุมมองที่ 3 + ปุ่มย้อนกลับ
5. เก็บ animation + reduced-motion + มือถือ (แตะ = เลือก, ไม่มี hover)
6. ตรวจด้วยเบราว์เซอร์จริงทุก breakpoint

**ทางเลือกเสริมภายหลัง:** อัปเกรดเป็น Three.js เฉพาะหน้า Landing เป็น hero โชว์ (orbit อัตโนมัติ) โดยหน้าเลือกห้องยังใช้ CSS 3D — ได้ความว้าวโดยไม่ผูกทั้งระบบกับ WebGL
