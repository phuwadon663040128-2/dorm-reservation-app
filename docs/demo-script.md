# สคริปต์นำเสนอ Mock-up — ระบบจองหอพักในกำกับ มข.

> ใช้เดโมให้อาจารย์ดูการทำงานครบทุกกรณี ตั้งแต่ผู้สมัครใหม่จนจบกระบวนการ
> เวลารวมประมาณ 12–18 นาที (ตัดตอนที่ 5–6 เหลือ ~8 นาทีได้)

## การเตรียมก่อนนำเสนอ

1. รัน `npm run dev` แล้วเปิด `http://localhost:5173`
2. **เปิด 2 หน้าต่าง**: หน้าต่างปกติ 1 บาน + หน้าต่าง incognito 1 บาน (ไว้สวมสองบทบาทพร้อมกัน เช่น ผู้เชิญ–ผู้ถูกเชิญ หรือ ผู้สมัคร–เจ้าหน้าที่)
3. ⚠️ ข้อมูลจำลองอยู่ในหน่วยความจำ — **รีเฟรชหน้า = รีเซ็ตทุกอย่างกลับสถานะตั้งต้น** ใช้ข้อนี้ให้เป็นประโยชน์: ซ้อมเสร็จรีเฟรชทีเดียว สถานะกลับเหมือนเดิมทั้งหมด (ห้ามรีเฟรชกลางเดโมถ้าไม่ตั้งใจรีเซ็ต)
4. บัญชีทั้งหมดเลือกจากหน้า **เข้าสู่ระบบ** ได้เลย ไม่ต้องกรอกรหัสผ่าน แต่ละบัญชีมีคำใบ้สถานการณ์กำกับ

### บัญชีเดโมและกรณีที่ผูกไว้

| บัญชี | สถานการณ์ตั้งต้น |
|---|---|
| ณิชา อุ่นเรือน + ภูริ พัฒนกุล | บัญชีว่าง — เดินจองใหม่สด ๆ ได้ตั้งแต่ต้น |
| ปริญญา สายชล + จิรายุ วงศ์สุข | จองห้อง 2101 แล้ว รอรูมเมทยืนยันภายใน 15 นาที (นับถอยหลังจริง) |
| ศุภกร ใจดี + ธนพล มั่นคง | ห้อง A102 (HL) อยู่ใน payment hold 72 ชม. — ศุภกรจ่ายครบ ธนพลจ่าย ROOM ค้าง HL |
| กมลชนก แสงทอง | โปรไฟล์ไม่ครบ — โดนระบบกันไม่ให้เชิญ/จอง |
| ณัฐวุฒิ ศรีสวัสดิ์ + พิมพ์ชนก บุญมา | ห้อง A201 ยืนยันถาวรแล้ว — สัญญาลงนามแล้ว 1 จาก 2 |
| วรัญญา พูนสุข | เหมาห้อง 3105 — สัญญาครบ รอรับกุญแจ |
| สมศักดิ์ ประจำหอ | เจ้าหน้าที่ สิทธิ์ครบทุกส่วนงาน |
| รัตนา แก้วประเสริฐ / ประวิทย์ อินทรชัย | เจ้าหน้าที่ถูกจำกัดสิทธิ์ (การเงิน / สัญญา) |
| เจ้าหน้าที่ใหม่ (ยังไม่ได้รับสิทธิ์) | ทดสอบจอไม่มีสิทธิ์ |
| กองบริการหอพัก (ผู้ดูแลระบบ) | Admin — กำหนดสิทธิ์เจ้าหน้าที่รายคน |

## ตอนที่ 1 — มุมมองสาธารณะ (ยังไม่เข้าสู่ระบบ) · ~2 นาที

**พูดนำ:** "ผู้สมัครยังไม่ต้องมีบัญชี KKU ก็เริ่มดูห้องได้เลย"

1. **หน้าแรก** — ชี้ป้าย "เปิดให้จอง + ช่วงวันที่", ค้นหาด้วยตัวกรอง (หอ/ประเภท/เพศ) กดค้นหาห้อง
2. **หน้าหอพัก (แผนผัง)** — จุดขายหลักของระบบ ชี้ทีละอย่าง:
   - ผังจัดวางตามแบบแปลนจริงของตึก (ปีกหลัก 2 แถวคั่นทางเดิน + โซนปีกหลังตึก + โถงบันได)
   - แท็บสลับชั้น (ชั้น 1/2/3) + ตัวเลขห้องว่างรายชั้น
   - สีสถานะ 4 แบบ: ว่าง (เขียว) / ถูกจองชั่วคราว (เหลือง + นับถอยหลัง) / จองแล้ว (เทา) / ไม่เปิดให้จอง (แดง)
   - ปุ่ม **"ดูผังจริง"** → modal แสดงแบบแปลนสถาปนิกจริงของหอ/ชั้นนั้น
   - ตัวกรอง "ประเภทห้อง = ห้องแอร์พิเศษ" → ห้องอื่นจางลงแต่ตำแหน่งไม่ขยับ (ยังอ่านผังออก)
3. กดห้องว่าง 1 ห้อง → dialog รายละเอียด: ขนาดห้อง สิ่งอำนวยความสะดวก **ประมาณการราคาแยกพักคู่/เหมาห้อง** (ห้อง HL ชี้ว่าแยก ROOM + HL สองรายการ) → ปุ่ม "เข้าสู่ระบบเพื่อจอง"

## ตอนที่ 2 — เคสหลัก: จองใหม่ตั้งแต่ต้นจนถึงรอชำระเงิน (live ทั้งหมด) · ~4 นาที

ใช้ **ณิชา** (หน้าต่างปกติ) + **ภูริ** (incognito)

**พูดนำ:** "เคสแรกคือผู้สมัครใหม่สองคนอยากพักคู่กัน — ตามข้อกำหนด ต้องจับคู่รูมเมทให้เสร็จก่อนถึงจะเลือกห้องได้"

| ขั้น | ทำที่ | การกระทำ | สิ่งที่ชี้ให้อาจารย์ดู |
|---|---|---|---|
| 2.1 | ณิชา → เมนู "รูมเมท" | ส่งคำเชิญหาภูริ | คำเชิญมีอายุ 48 ชม. · 1 คนมีได้ 1 คำเชิญ/กลุ่ม |
| 2.2 | ภูริ → "รูมเมท" | กด **ตอบรับ** | สถานะกลุ่มเปลี่ยนเป็น "จับคู่แล้ว" ทั้งสองฝั่ง |
| 2.3 | ณิชา → "เลือกห้องพัก" | เลือกห้องว่าง → เลือก **พักคู่ (2 คน)** → จอง | หัวหน้ากลุ่มเท่านั้นที่กดจองได้ · ห้องถูก **ล็อกทันที** |
| 2.4 | เปิดหน้าหอพักสาธารณะ (แท็บใหม่) | — | ห้องเดียวกันขึ้น "ถูกจองชั่วคราว" + เวลานับถอยหลัง — คนอื่นกดจองไม่ได้ (กันจองซ้อน) |
| 2.5 | ภูริ → "การจองของฉัน" | กด **ยืนยันห้อง** ภายใน 15 นาที | นับถอยหลัง 15 นาทีของจริง · ถ้าปฏิเสธ = ปล่อยห้องคืนทันที |
| 2.6 | ทั้งคู่ → "ชำระเงิน" | — | เข้าสู่ **payment hold 72 ชม.** deadline เดียวร่วมกัน · ภาระชำระแยกรายคน (ห้อง HL = 4 รายการ: ROOM+HL × 2 คน) · Ref.1 = เลขห้อง (ซ้ำกันได้) Ref.2 = ROOM2569/HL2569 |

**เคสย่อยที่ควรสาธิตต่อทันที (รีเฟรชก่อนแล้วทำใหม่):**
- **2A ปฏิเสธห้อง:** ทำซ้ำ 2.1–2.3 แล้วให้ภูริกด "ปฏิเสธ (ปล่อยห้องทันที)" → เปิดหน้าสาธารณะให้เห็นห้องกลับมาว่างทันที
- **2B เหมาห้อง:** ณิชา (ยังไม่มีกลุ่ม) → เลือกห้องที่รองรับเหมาห้อง → เลือก **เหมาห้อง (1 คน)** → จองได้เลยไม่ต้องมีรูมเมท → ภาระชำระเป็นราคาเต็มห้อง 1 ชุด สัญญา 1 ฉบับ
- **2C โปรไฟล์ไม่ครบ:** สลับเป็น **กมลชนก** → พยายามเชิญรูมเมท/จอง → ระบบกันพร้อมเหตุผล "โปรไฟล์ยังไม่ครบ" (กติกา AUTH-007)

## ตอนที่ 3 — เคสสถานะกลางทาง (บัญชีที่ seed ไว้แล้ว) · ~3 นาที

**พูดนำ:** "สามบัญชีต่อไปนี้จำลองสถานะที่เกิดขึ้นจริงระหว่างกระบวนการ"

- **3A รอยืนยัน 15 นาที:** เข้าเป็น **จิรายุ** → หน้า "การจองของฉัน" มีการ์ด "ยืนยันห้อง 2101" พร้อมนับถอยหลังเหลือ ~9 นาที → กดยืนยันให้ดูสด ๆ ว่าเปลี่ยนเป็น payment hold 72 ชม. (ฝั่ง **ปริญญา** หัวหน้ากลุ่มจะเห็นสถานะเดียวกัน)
- **3B จ่ายครบคนเดียว (เคสสำคัญที่สุดด้านการเงิน):** เข้าเป็น **ศุภกร** → "ชำระเงิน": ของตัวเองจ่ายครบ แต่การ์ดสถานะกลุ่มแสดงว่า **ธนพลจ่าย ROOM แล้ว ค้าง HL** → ห้องยังไม่ยืนยันถาวร
  **ประโยคสำคัญ:** "ตามกติกา ห้องจะยืนยันถาวรก็ต่อเมื่อ *ทุกคนในกลุ่มจ่ายครบทุกรายการ* แล้วเจ้าหน้าที่กดยืนยันเท่านั้น ถ้าเกิน 72 ชม. ระบบจะปล่อยห้องและส่งยอดที่จ่ายแล้วเข้าคิวคืนเงิน/ตรวจสอบโดยเจ้าหน้าที่ — ค่านี้ยังเป็นกติกาชั่วคราว (Provisional) รอผู้มีส่วนได้ส่วนเสียยืนยัน"
- **3C สถานะแยกการ์ดไม่รวมก้อน:** ชี้ว่าหน้า "การจองของฉัน" แสดงการ์ดแยก ห้อง/รูมเมท/hold/ชำระเงินรายรายการ/สัญญา/กุญแจ — ไม่ยุบเป็นสถานะเดียวคลุมเครือ (ตามเอกสาร UX ข้อ 03)

## ตอนที่ 4 — หลังยืนยันถาวร: สัญญา → กุญแจ (จบกระบวนการฝั่งผู้พัก) · ~2 นาที

- **4A สัญญากลุ่มลงนามไม่ครบ:** เข้าเป็น **ณัฐวุฒิ** → "สัญญา": ห้อง A201 ยืนยันแล้ว มีสัญญา 2 ฉบับใต้กลุ่มเดียว สถานะ **"ลงนามแล้ว 1 จาก 2"** → กด **พิมพ์สัญญา** (ระบบบันทึกประวัติการพิมพ์ทุกครั้ง — audit)
- **4B อีกคนยังไม่ส่งสัญญา:** สลับเป็น **พิมพ์ชนก** → เห็นฝั่งตัวเองยังค้าง → ปุ่มอัปโหลดสแกนสัญญา (ไฟล์เก็บ private) — ชี้ว่ากลุ่มจะสมบูรณ์เมื่อรับสัญญาครบทั้งสองฉบับ
- **4C จบกระบวนการ:** เข้าเป็น **วรัญญา** (เหมาห้อง 3105) → สัญญาครบแล้ว → หน้า "รับกุญแจ/ขั้นตอนถัดไป" แสดงว่ารอส่งมอบกุญแจ ซึ่งเป็น **เอกสารลงนามแยกอีกฉบับ** ผูกกับสัญญา — นี่คือสถานะสุดท้ายของผู้พักในระบบ ก่อนข้อมูลเข้าคิวส่งต่อระบบมหาวิทยาลัย

## ตอนที่ 5 — ฝั่งเจ้าหน้าที่: การเงิน SCB ครบวงจร · ~4 นาที

เข้าเป็น **สมศักดิ์ ประจำหอ** (สิทธิ์เต็ม)

**พูดนำ:** "ระบบเราไม่ได้สร้าง QR เอง แต่เตรียมข้อมูลและเชื่อมขั้นตอนกับโปรแกรม SCB เดิมผ่านไฟล์ 3 ชนิด: Excel ขาออก, PDF ขากลับ, รายงานผลชำระ"

1. **Dashboard** — ตัวเลขคิวงานทั้งหมดคำนวณจากข้อมูลห้องจริง (ห้องว่าง, รอยืนยัน 15 นาที, รอชำระ 72 ชม., กลุ่มจ่ายไม่ครบ, exception เปิดอยู่, รอส่งมอบกุญแจ, คิวส่งมหาวิทยาลัย)
2. **ห้องที่ถูก hold** — รายการ hold พร้อมเวลาคงเหลือ (เห็นกลุ่มของปริญญา/ศุภกรที่เดโมไปตอน 2–3)
3. **รายการชำระเงิน → Export batch (SLIPS)** — กดสร้าง batch: ชี้คอลัมน์ตรง template ธนาคารเป๊ะ (ID เว้นว่าง · Ref.1 เลขห้อง · Ref.2 ROOM2569/HL2569 · 1 แถว = 1 คน × 1 รายการ — รูมเมทมี Ref ซ้ำกันได้)
4. **นำเข้า PDF จากธนาคาร** — จำลองรับ PDF รวมหลายหน้า: ระบบ match หน้าให้ผู้พักอัตโนมัติ **โดยไม่ใช้ลำดับหน้า/Ref อย่างเดียว** · มีหน้า **กำกวม 2 หน้า** ค้างในคิว → เดโม **manual match** (บังคับใส่เหตุผล + เก็บ mapping เดิมเป็นประวัติ)
5. **ผลชำระ / Exception** — นำเข้ารายงานผล: รายการปกติจับคู่อัตโนมัติ ผิดปกติเข้าคิว **ไม่ยืนยัน/ปัดตกอัตโนมัติ** → ชี้ 4 เคสในคิว (จ่ายขาด/จ่ายเกิน/รายการซ้ำ/จ่ายช้า) + นำเข้าซ้ำได้ไม่เกิดรายการซ้ำ (idempotent)
6. **สัญญา → ส่งมอบกุญแจ → ส่งข้อมูลมหาวิทยาลัย** — บันทึกรับสัญญาลงนาม, บันทึกส่งมอบกุญแจ, คิว handoff (แก้ไขภายหลัง = สร้าง correction ใหม่ ไม่ทับของเดิม)
7. **Audit log** — ทุกการกระทำสำคัญมีผู้ทำ/เวลา/เหตุผล

> หน้า "จองแทน (manual)", "รอบรับสมัคร", "รายงาน", "ตั้งค่า", "ต่อสัญญา" เป็น **หน้าข้อกำหนด (spec placeholder)** — เปิดให้อาจารย์เห็นว่าขอบเขตกำหนดไว้แล้ว แต่อย่าเผลอกดเดโมเป็นฟีเจอร์จริง

## ตอนที่ 6 — RBAC: บทบาทและสิทธิ์ · ~2 นาที

**พูดนำ:** "เจ้าหน้าที่มีบทบาทเดียว แต่ผู้ดูแลระบบเลือกได้ว่าแต่ละคนเข้าถึงส่วนงานไหน"

1. เข้าเป็น **รัตนา** → เมนูเหลือเฉพาะการเงิน SCB → พิมพ์ URL `/staff/contracts` ตรง ๆ → ถูกเด้งกลับ (กันทั้งเมนูและ URL)
2. เข้าเป็น **เจ้าหน้าที่ใหม่** → เจอจอ "ยังไม่ได้รับสิทธิ์เข้าถึงส่วนงาน ติดต่อผู้ดูแลระบบ"
3. เข้าเป็น **กองบริการหอพัก (ผู้ดูแลระบบ)** → เมนู "จัดการสิทธิ์เจ้าหน้าที่" → **เปิด/ปิดสวิตช์สด ๆ** (เช่น เปิดส่วนงานสัญญาให้รัตนา) → บอกอาจารย์ว่าการเปลี่ยนสิทธิ์ทุกครั้งต้องบันทึก audit
4. (แถม) สลับ **โหมดมืด/สว่าง** และย่อจอเป็นมือถือ — ฝั่งผู้สมัครออกแบบ mobile-first

## ปิดท้าย: ประโยคสรุปที่ควรพูด

> "Mock-up นี้ครอบคลุม workflow จริงตั้งแต่ผู้สมัครยังไม่มีบัญชี KKU → จับคู่รูมเมท → ล็อกห้องจริงกันจองซ้อน → ภาระชำระแยกรายคนตามโครงสร้าง ROOM/HL ของ SCB → เจ้าหน้าที่ตรวจและยืนยัน → สัญญากระดาษ 2 ฉบับต่อกลุ่ม → ส่งมอบกุญแจ → คิวส่งต่อระบบมหาวิทยาลัย โดยค่าที่นโยบายยังไม่นิ่ง (เช่น ผลลัพธ์กรณีจ่ายไม่ครบใน 72 ชม.) ติดป้าย Provisional ไว้รอการยืนยันจากผู้มีส่วนได้ส่วนเสีย ไม่ได้เขียนตายในระบบ"

### ข้อควรระวังตอนพรีเซนต์ (คำที่ห้ามพูด — จากเอกสารเตรียมนำเสนอ)
- ❌ "ระบบสร้าง QR เอง" → ✅ "ระบบเตรียมไฟล์ให้โปรแกรม SCB เดิม"
- ❌ "กดจองแล้วได้ห้องทันที" → ✅ "กดจองแล้วห้องถูกล็อกชั่วคราว ยืนยันถาวรเมื่อจ่ายครบ + เจ้าหน้าที่ตรวจ"
- ❌ "Ref.1/Ref.2 ใช้ระบุตัวคนได้" → ✅ "รูมเมทใช้ Ref ซ้ำกันได้ ระบบใช้ ID ภายในเป็นหลัก"
