# 16 — Audit Log (`/staff/audit`)

> ต้องอ่าน `00-design-system.md` ก่อน · ออกแบบ 3 แนวทาง A/B/C ตามนิยามในไฟล์นั้น

**ทำจอนี้เป็นจอแรก ๆ** — เป็นจอที่มี filter/ตาราง/dialog ครบที่สุด สิ่งที่ได้จะกลายเป็นแม่แบบให้จออื่น

## จอนี้คืออะไร

บันทึกว่าใครทำอะไรเมื่อไร ด้วยเหตุผลอะไร — ตรวจสอบย้อนหลังได้ถึงระดับ payload ดิบ

ทุกการกระทำที่เปลี่ยนสถานะในระบบต้องมี audit event **นี่คือจอที่รองรับ compliance ทั้งระบบ**

## ปัญหาที่ต้องแก้

1. **audit log จริงจะมีเป็นหมื่นแถว** — ตารางนี้ render ทุกแถวที่ผ่าน filter ไม่มี pagination
2. **ไม่มี filter ตามวัตถุที่ถูกกระทำ** — คำถามที่ถามบ่อยที่สุดคือ
   "ห้อง 1325 มีอะไรเกิดขึ้นบ้าง" หรือ "นักศึกษาคนนี้ถูกทำอะไรบ้าง"
   แต่ค้นได้แค่ผ่านช่องค้นหารวมที่ไล่ทุกฟิลด์
3. **ช่วงเวลาเป็น preset 4 อัน** — เลือกช่วงเองไม่ได้ ทั้งที่งานตรวจสอบมักระบุวันที่แน่นอน
4. **JSON เปิดทีละอัน** — เทียบ 2 เหตุการณ์ไม่ได้ ทั้งที่งาน audit คือการเทียบก่อน/หลัง
5. **ไม่เห็นความสัมพันธ์ระหว่างเหตุการณ์** — `relatedIds` มีอยู่แล้วแต่แสดงเป็นข้อความ กดไม่ได้
   ทั้งที่มันคือกุญแจของการไล่ร่องรอย
6. **คอลัมน์ "เหตุผล / อ้างอิง" แคบ 176px** และ `line-clamp-3` — เหตุผลคือข้อมูลสำคัญที่สุดของ audit
   แต่ถูกบีบมากที่สุด
7. **ไม่มี export** — งานตรวจสอบต้องส่งหลักฐานออกไปได้
8. ตาราง `min-w-225` (900px) → บนจอแคบต้องเลื่อนแนวนอน

## โจทย์เฉพาะจอนี้

- **A (Console):** toolbar ยุบเป็นแถวเดียว filter รองอยู่ใน popover · filter ที่ทำงานเป็น chip ถอดได้
  · เพิ่ม date range picker · แถวกระชับลง เหตุผลย้ายไปคอลัมน์กว้างขึ้น
  · คลิกแถวเปิด drawer ที่มีทั้งข้อความอ่านง่ายและ JSON ดิบ
  · `relatedIds` กดได้ → กรองเหตุการณ์ที่เกี่ยวกับ id นั้นทันที
  · virtual scroll หรือ pagination + คีย์ลัดไล่แถว
- **B (Workflow):** จัดเป็น **ไทม์ไลน์เชิงเวลา** จัดกลุ่มตามวัน แล้วในแต่ละวันจัดตามเหตุการณ์ที่ต่อเนื่องกัน
  (เหตุการณ์ที่มี `relatedIds` ร่วมกันจับเป็นสายเดียว)
  ทำให้อ่าน "เรื่องราว" ได้ ไม่ใช่แค่รายการ — ตอบโจทย์ตอนต้องอธิบายว่าเกิดอะไรขึ้นกับเคสหนึ่ง
- **C (Focus + Split):** ซ้ายเป็นรายการเหตุการณ์กระชับ ขวาเป็นรายละเอียดเต็ม:
  ข้อความอ่านง่าย + เหตุผลเต็ม + JSON ดิบ + **เหตุการณ์อื่นที่เกี่ยวข้อง** (ผ่าน `relatedIds`)
  + ปุ่ม "เหตุการณ์ก่อนหน้า/ถัดไปของวัตถุเดียวกัน" — ทำให้ไล่ร่องรอยได้ต่อเนื่อง

## เงื่อนไขเพิ่ม

- **ต้องมีคำตอบเรื่องข้อมูลหมื่นแถว** — virtual scroll หรือ pagination พร้อมบอกจำนวนหน้า
- **`relatedIds` ต้องกดได้** และควรลิงก์ไปจอที่เกี่ยวข้องได้ด้วยถ้าเป็นไปได้
- ต้องมี **date range picker** ไม่ใช่แค่ preset
- ต้องมี **export ผลที่กรองอยู่** (CSV/JSON) พร้อม audit ของการ export เอง
- ปุ่มคัดลอก JSON ต้องรองรับกรณี clipboard API ใช้ไม่ได้ (มีอยู่แล้ว — คงไว้)
- audit log เป็น **read-only เสมอ** — ห้ามมี UI ที่สื่อว่าแก้ไข/ลบได้
- ต้องมีสภาพ **ไม่มีสิทธิ์** (`audit.view`)
