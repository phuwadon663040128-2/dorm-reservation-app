# 15 — รายงาน (`/staff/reports`)

> ต้องอ่าน `00-design-system.md` ก่อน · ออกแบบ 3 แนวทาง A/B/C ตามนิยามในไฟล์นั้น

## สถานะปัจจุบัน

**ยังเป็น `PlaceholderPage` — ออกแบบจากศูนย์** (เฟส P6)

## จอนี้คืออะไร

รายงานปฏิบัติการสำหรับส่งต่อ workflow เดิมของหน่วยงาน — งานส่วนใหญ่จบที่ **export CSV/Excel**
ไม่ใช่การดูบนจอ

> **ทุกไฟล์ export ต้อง minimize ข้อมูลส่วนบุคคลตามประเภทรายงาน (PDPA)**

## รายงานที่ต้องมี (เอกสาร 05 §Reports)

### กลุ่มห้องและการจอง
- สถานะห้องจริงรายห้อง
- กลุ่มรูมเมทและหัวหน้ากลุ่ม
- hold ที่กำลังจะหมดเวลา

### กลุ่มการเงิน
- รายการชำระเงินตาม action (ROOM / HL) และความครบของกลุ่ม
- สถานะ SCB batch
- หน้า PDF ที่ยัง match ไม่ได้
- exception และการคืนเงิน

### กลุ่มสัญญาและส่งต่อ
- สัญญาและการส่งมอบกุญแจ
- การส่งข้อมูลมหาวิทยาลัยและ correction

## ปัญหาที่ต้องแก้ (โจทย์ตั้งต้น)

1. **รายงาน 9 ชนิดใน 3 กลุ่ม** — จะจัดยังไงไม่ให้เป็นแค่รายการลิงก์ยาว ๆ
2. **แต่ละรายงานมีพารามิเตอร์ต่างกัน** (ช่วงเวลา, กลุ่มหอ, รอบรับสมัคร, สถานะ)
   จะออกแบบฟอร์มพารามิเตอร์ยังไงไม่ให้ต้องทำ 9 หน้าแยก
3. **PDPA: แต่ละรายงาน minimize ข้อมูลไม่เท่ากัน** — ต้องมี visual บอกว่ารายงานนี้มีข้อมูลส่วนบุคคลระดับไหน
   และใครมีสิทธิ์ export
4. **ดูบนจอ vs. ดาวน์โหลด** — บางรายงานควรดูบนจอก่อน บางอันดาวน์โหลดอย่างเดียว จะแยกยังไง
5. **ไม่มีประวัติการ export** — ใครดาวน์โหลดรายงานที่มีข้อมูลส่วนบุคคลไปเมื่อไร ต้องตามได้ (audit)
6. **รายงานที่ใช้บ่อยกับใช้นาน ๆ ที** ปะปนกัน

## โจทย์เฉพาะจอนี้

- **A (Console):** ตารางรายงานทั้งหมดในหน้าเดียว (ชื่อ · กลุ่ม · ระดับข้อมูลส่วนบุคคล · รูปแบบไฟล์ · ใช้ล่าสุด)
  · คลิกเปิด drawer ที่มีฟอร์มพารามิเตอร์ + preview 20 แถวแรก + ปุ่มดาวน์โหลด
  · มีส่วน "รายงานที่ใช้บ่อย" ปักหมุดไว้บนสุด
- **B (Workflow):** **wizard สร้างรายงาน** — เลือกกลุ่ม → เลือกรายงาน → ตั้งพารามิเตอร์
  → ตรวจทาน (บอกชัดว่าไฟล์จะมีข้อมูลส่วนบุคคลอะไรบ้าง กี่แถว) → ดาวน์โหลด
  ขั้นตรวจทานคือหัวใจ เพราะเป็นจุดที่ผู้ใช้ต้องรับรู้ผลกระทบ PDPA ก่อนกด
- **C (Focus + Split):** ซ้ายเป็น catalog รายงานจัดเป็น 3 กลุ่ม ขวาเป็น **หน้ารายงานเต็ม**:
  พารามิเตอร์ด้านบน ตารางผลลัพธ์สดด้านล่าง ปุ่ม export มุมขวา
  ดูบนจอได้จริงก่อนดาวน์โหลด — เหมาะกับการตอบคำถามเฉพาะหน้า

## เงื่อนไขเพิ่ม

- **ทุกรายงานต้องมีป้ายระดับข้อมูลส่วนบุคคล** เช่น "ไม่มีข้อมูลส่วนบุคคล" / "มีชื่อ-ห้อง" / "มีข้อมูลติดต่อ"
  ใช้ badge ตามระบบสีในข้อ 8 ของ design system
- การ export รายงานที่มีข้อมูลส่วนบุคคลต้อง **บันทึก audit** — แจ้งผู้ใช้ให้ทราบก่อนกด
- ต้องมี **ประวัติการ export** อย่างน้อยของตัวเอง (ใคร รายงานอะไร เมื่อไร พารามิเตอร์อะไร)
- ถ้าจะมีกราฟ ให้ใช้ `--chart-1` ถึง `--chart-5` เท่านั้น
  และ**ห้ามใช้ไลบรารีชาร์ตภายนอก** — วาดด้วย SVG/div เอง
- รายงานที่ผู้ใช้ไม่มีสิทธิ์เข้าถึงส่วนงานนั้น ต้องไม่แสดง (หรือแสดงแบบล็อกพร้อมเหตุผล)
- ต้องออกแบบสภาพ "รายงานว่างเปล่า" (query แล้วไม่มีข้อมูล) ให้ต่างจาก "ยังไม่ได้ query"

## หมายเหตุ

จอนี้ยังไม่มีข้อมูลจริงในโปรเจกต์ ให้สมมติโครงสร้างข้อมูลจาก store ที่มี:
`useDormStore`, `useReservationStore`, `usePaymentsStore`, `useContractsStore`
