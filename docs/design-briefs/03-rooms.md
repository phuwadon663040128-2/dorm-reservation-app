# 03 — อาคาร / ชั้น / ห้อง (`/staff/rooms`)

> ต้องอ่าน `00-design-system.md` ก่อน · ออกแบบ 3 แนวทาง A/B/C ตามนิยามในไฟล์นั้น

**ทำจอนี้เป็นจอแรก** — เป็นจอที่มี toolbar/filter/ตารางครบที่สุด สิ่งที่ได้จะกลายเป็นแม่แบบให้จออื่น

## จอนี้คืออะไร

รายการห้องจริงทั้งหมดในระบบ **ห้องจริงเป็น source of truth ของการจองทั้งหมด — เลขห้อง unique ทั้งระบบ**
ข้อมูลระดับหลายร้อยแถว ต้องหาห้องเจอเร็วและเห็นสถานะได้ทันที

## ข้อมูลที่มีจริง

### หัวเพจ
- title: "อาคาร / ชั้น / ห้อง"
- description: "ห้องจริงเป็น source of truth ของการจองทั้งหมด — เลขห้อง unique ทั้งระบบ"
- icon: `Building2Icon`
- action: ปุ่ม outline "นำเข้า Room Master" (`ImportIcon`)

### Toolbar filter (ปัจจุบัน grid 12 คอลัมน์)
| ช่อง | ชนิด | ค่า |
|---|---|---|
| ค้นหาห้อง | Input + SearchIcon | placeholder "เลขห้อง อาคาร ประเภท หรือเหตุผล block" |
| กลุ่มหอ | Select | ทุกกลุ่มหอ + รายการ `dormGroups` (แสดง `shortName`) |
| อาคาร | Select | ทุกอาคาร + `buildings` (กรองตามกลุ่มหอที่เลือก) |
| ชั้น | Select | ทุกชั้น + เลขชั้นที่มีจริง (กรองตามกลุ่มหอ+อาคาร) |
| ประเภทห้อง | Select | ทุกประเภท + `roomConfigLabel` |
| สถานะ | Select | ทุกสถานะ + `roomPublicStatusLabel` |

**Select แบบ cascade:** เปลี่ยนกลุ่มหอ → รีเซ็ตอาคารและชั้น · เปลี่ยนอาคาร → รีเซ็ตชั้น

### แถวเรียง/สรุป (ใต้ toolbar, `border-t pt-3`)
- ซ้าย: "พบ **X** จาก Y ห้อง" (`aria-live="polite"`)
- ขวา: Select เรียง 5 ตัวเลือก — เลขห้องน้อย→มาก / เลขห้องมาก→น้อย / อาคาร-ชั้น / ชั้นน้อย→มาก / สถานะห้อง
- ปุ่ม ghost "ล้างตัวกรอง" (`XIcon`) โผล่เมื่อมี filter ใดทำงาน

### คอลัมน์ตาราง
| คอลัมน์ | รูปแบบ |
|---|---|
| ห้อง | `font-semibold tabular-nums` |
| กลุ่มหอ / อาคาร / ชั้น | ชื่ออาคารตัวหนา + " · ชั้น N · {ชื่อกลุ่มหอ}" สีจาง |
| ประเภท | `roomConfigLabel[config]` |
| ขนาด | `dimensions` หรือ "ไม่มีข้อมูล" |
| สถานะ | `RoomStatusBadge` + บรรทัดเล็ก "เหตุผล: {blockedReason}" ถ้ามี |
| จัดการ | ปุ่ม ghost "Block" / "ปลด block" (ชิดขวา) |

Empty: "ไม่พบห้องตามคำค้นหาและตัวกรองที่เลือก" (`h-32 text-center`)

ทั้งจอครอบด้วย `<PermissionGate permission="room.manage">`

## กฎธุรกิจ

- **การ block ห้องต้องมีเหตุผลบังคับ + บันทึก audit** (เอกสาร 05)
- **นำเข้า Room Master** ต้องมี preview → ตรวจซ้ำ → นำเข้าซ้ำได้แบบ idempotent
- ห้อง 1325 เป็นห้อง "แอร์พิเศษ" — มีเคสพิเศษที่ต่างจากห้องอื่น
- โปรเจกต์มี **ผังชั้น PNG ใน `public/plans`** และมี room picker แบบดูผังอยู่ฝั่งนักศึกษาแล้ว

## ปัญหาที่ต้องแก้

1. **filter 6 ช่องกิน 2 บรรทัดเต็ม** เหลือพื้นที่ให้ตารางน้อย — บนจอ 1440px เห็นแค่ ~10 แถว
2. **ไม่เห็นภาพรวมเชิงพื้นที่** — ข้อมูลเป็นตารางล้วน ทั้งที่มีผังชั้นอยู่แล้ว
   เจ้าหน้าที่คิดเป็น "อาคาร → ชั้น → ห้อง" ไม่ใช่ "แถวที่ 47"
3. **ไม่มี bulk action** — block ทั้งชั้นตอนซ่อมต้องกดทีละห้อง
4. **filter ที่ทำงานอยู่ดูยาก** — ต้องกวาดตาดู Select ทั้ง 5 ตัวว่าตัวไหนไม่ใช่ "ทุก..."
5. **ไม่เห็นว่าห้องนี้ใครจองอยู่** — ต้องข้ามไปจออื่น

## โจทย์เฉพาะจอนี้

- **A (Console):** toolbar ยุบเป็นแถวเดียว — ค้นหา + filter หลัก 2 ตัว ที่เหลือใน popover
  filter ที่ทำงานเป็น chip ถอดได้ · checkbox เลือกหลายห้อง → bulk block/unblock
  · คลิกแถวเปิด drawer ขวาที่มีข้อมูลห้อง + ผู้จองปัจจุบัน + ประวัติ block
- **B (Workflow):** จัดตาม **ลำดับชั้นเชิงพื้นที่** — กลุ่มหอ → อาคาร → ชั้น เป็น navigation จริง
  ไม่ใช่ filter เลือกชั้นแล้วเห็น **ผังห้องเป็นตาราง grid** สีตามสถานะ กดห้องแล้วจัดการได้เลย
  มีมุมมองสลับ "ผัง / ตาราง"
- **C (Focus + Split):** ซ้ายเป็น tree อาคาร-ชั้นพร้อมตัวเลขสรุปแต่ละชั้น (ว่าง/จอง/block)
  ขวาเป็นรายการห้องของชั้นที่เลือก + รายละเอียดห้องเมื่อคลิก

## เงื่อนไขเพิ่ม

- ปุ่ม Block ต้องเปิด dialog ที่มี **ช่องเหตุผลบังคับ** (ห้ามส่งว่าง) ก่อนบันทึก
- ต้องออกแบบ flow **"นำเข้า Room Master"** ให้ครบ: อัปโหลด → preview ความต่าง (เพิ่ม/แก้/ซ้ำ) → ยืนยัน
- ถ้าใช้ผัง ให้ทำผังเป็น grid ของ div ธรรมดา ไม่ต้องพึ่งไฟล์ PNG จริง (จะต่อทีหลัง)
- ตารางระดับหลายร้อยแถว → ต้องมีคำตอบเรื่อง pagination หรือ virtual scroll
