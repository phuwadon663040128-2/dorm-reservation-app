# บรีฟออกแบบ UI ฝั่งเจ้าหน้าที่ — ระบบจองหอพักในกำกับ มข.

ชุดเอกสารสำหรับส่งให้ Claude ออกแบบ UI ทีละจอ

## วิธีใช้

**ทุกครั้งที่เปิดแชตใหม่ ให้แนบ 2 ไฟล์:**

1. `00-design-system.md` — ธีม สี ฟอนต์ คอมโพเนนต์ และ **นิยาม 3 แนวทาง** (ไฟล์นี้เหมือนกันทุกรอบ)
2. ไฟล์บรีฟของจอที่ต้องการ เช่น `01-dashboard.md`

แล้วพิมพ์สั้น ๆ ว่า:

> อ่าน 00-design-system.md แล้วออกแบบจอตาม 01-dashboard.md ให้ครบทั้ง 3 แนวทาง (A/B/C)

**หนึ่งแชต = หนึ่งจอ** อย่ารวมหลายจอในแชตเดียว จุดประสงค์ของการแยกไฟล์คือให้แต่ละจอได้รายละเอียดเต็มที่

## 3 แนวทางที่ขอทุกจอ

| | ชื่อ | หลักคิด |
|---|---|---|
| **A** | Console | หนาแน่นสูงสุด ตารางเป็นพระเอก รายละเอียดเปิดใน drawer — เร็วสำหรับคนใช้ทุกวัน |
| **B** | Workflow | จัดตามลำดับขั้นของงาน แยก "ต้องตัดสินใจ" ออกจาก "ดูเฉย ๆ" — ปลอดภัยสำหรับคนใหม่ |
| **C** | Focus + Split | master–detail สองคอลัมน์ถาวร ทำงานทีละเคสโดยไม่เสียบริบท — ดีสำหรับงานตรวจสอบ |

นิยามเต็มอยู่ใน `00-design-system.md` — **ห้ามให้ Claude คิดแนวทางเอง** เพราะต้องให้ 18 จอประกอบกันเป็นระบบเดียวได้

## ลำดับที่แนะนำให้ทำ

1. **03-rooms** และ **16-audit** ก่อน — สองจอนี้มี toolbar/filter/ตารางครบที่สุด สิ่งที่ได้จะกลายเป็นแม่แบบให้จออื่น
2. **01-dashboard** — เป็นหน้าแรกที่ทุกคนเห็น
3. **11-payment-results**, **10-pdf-import** — งานที่ซับซ้อนและเสี่ยงผิดพลาดที่สุด
4. ที่เหลือตามสะดวก

พอได้ 2–3 จอแรกแล้ว ให้แปะผลลัพธ์กลับเข้า `00-design-system.md` เป็นแม่แบบที่ตัดสินใจแล้ว จอถัด ๆ ไปจะสม่ำเสมอขึ้นมาก
