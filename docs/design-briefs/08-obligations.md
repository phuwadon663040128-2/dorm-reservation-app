# 08 — รายการชำระเงิน / Obligations (`/staff/obligations`)

> ต้องอ่าน `00-design-system.md` ก่อน · ออกแบบ 3 แนวทาง A/B/C ตามนิยามในไฟล์นั้น

## จอนี้คืออะไร

รายการหนี้ที่ต้องชำระทั้งหมดในระบบ — เป็นตารางตั้งต้นของงานการเงินทั้งสาย

**นิยามที่ต้องเข้าใจก่อนออกแบบ:**
> 1 รายการ = ผู้พัก 1 คน × 1 payment action
> ห้อง HL (เหมาห้อง) สร้าง **ROOM + HL แยกกัน 2 รายการ**
> **Ref.1 + Ref.2 ซ้ำกันได้ระหว่างรูมเมท — ไม่ใช่ unique key**

ข้อสุดท้ายสำคัญมากในการออกแบบ: **ห้ามให้ UI ทำให้คนเข้าใจว่า Ref คู่หนึ่งชี้คนเดียว**

## กฎธุรกิจ

- **Override ทำได้ครั้งเดียว เฉพาะบทบาทการเงิน ต้องมีเหตุผลบังคับ + audit**
- **Override ไม่แตะ pricing rule ถาวร** — มีผลเฉพาะรายการนั้น (PRICE-005/006)
- obligation ที่พร้อมส่งออกจะไปโผล่ที่จอ SCB Export
- ผลชำระมาจากรายงานที่นำเข้าที่จอ Results — จอนี้เป็นฝั่ง "หนี้" ไม่ใช่ฝั่ง "การชำระ"

## ปัญหาที่ต้องแก้

1. **ไม่มี filter ไม่มีค้นหา ไม่มีเรียงลำดับเลย** — ทั้งที่นี่คือตารางที่จะยาวที่สุดในระบบ
   (จำนวนผู้พัก × จำนวน action) หาของไม่เจอแน่นอน
2. **ไม่เห็นว่ารายการไหนคู่กับรายการไหน** — ห้อง HL มี ROOM + HL 2 แถว, รูมเมท 2 คนมี Ref ซ้ำกัน
   ตารางแบนราบทำให้ความสัมพันธ์นี้หายไปหมด ทั้งที่มันคือแก่นของโดเมน
3. **ไม่มีคอลัมน์ประเภท action** — แยกไม่ออกว่าแถวไหน ROOM แถวไหน HL
4. **ไม่มียอดรวม** — งานการเงินต้องเห็นยอดรวมของสิ่งที่กรองอยู่
5. **Ref.1 ใช้ค่า `roomNumber`** ซึ่งทำให้ดูเหมือนเป็นคอลัมน์ห้อง ไม่ใช่ reference ธนาคาร — น่าสับสน
6. ไม่มีเส้นทางไปดูว่าสถานะ "ยังไม่ชำระ" นี้เกิดจากอะไร

## โจทย์เฉพาะจอนี้

- **A (Console):** toolbar เต็ม (ค้นหาชื่อ/Ref · filter สถานะชำระ · filter ประเภท action · filter ห้อง · ช่วงยอด)
  + คอลัมน์ประเภท action + แถบยอดรวมของผลลัพธ์ที่กรอง + เลือกหลายแถวเพื่อส่งออกเป็น batch
  · คลิกแถวเปิด drawer ที่แสดงรายการอื่นของคนเดียวกันและของกลุ่มเดียวกันด้วย
- **B (Workflow):** จัดตาม **สถานะการชำระ** เป็น section — รอชำระ / ชำระแล้ว / exception / เกินกำหนด
  โดยแต่ละ section มียอดรวมและจำนวน ให้ภาพว่าเงินค้างอยู่ตรงไหนเท่าไร
  แล้วมีปุ่มลัดไปสร้าง export batch จากกลุ่ม "รอชำระ" โดยตรง
- **C (Focus + Split):** **จัดกลุ่มตามการจอง** — ซ้ายเป็นรายการ "ห้อง + กลุ่มผู้พัก"
  ขวาแตกเป็นรายการ obligation ทั้งหมดของกลุ่มนั้น เห็นชัดว่าใครมีกี่รายการ ครบยัง
  วิธีนี้แก้ปัญหาข้อ 2 ตรงที่สุด เพราะสะท้อนโครงสร้างจริงของโดเมน

## เงื่อนไขเพิ่ม

- **ต้องออกแบบให้ Ref.1+Ref.2 ที่ซ้ำกันเห็นชัดว่าซ้ำโดยตั้งใจ** ไม่ใช่ข้อผิดพลาด
  (เช่น จับคู่แถวที่ Ref เดียวกันด้วยเส้นเชื่อมหรือพื้นหลังกลุ่มเดียวกัน + คำอธิบายกำกับ)
- ปุ่ม Override ต้องเปิด dialog ที่มี: ยอดเดิม → ยอดใหม่ · **เหตุผลบังคับ** ·
  คำเตือนว่า "มีผลเฉพาะรายการนี้ ไม่เปลี่ยน pricing rule" · ทำได้ครั้งเดียว
- ยอดเงินใช้ `formatBaht()` เสมอ และจัดชิดขวาพร้อม `tabular-nums`
- ต้องมีสภาพ **ดูได้อย่างเดียว** (ไม่มีสิทธิ์ override) ที่ไม่ทำให้จอดูพัง — ไม่ใช่แค่ซ่อนคอลัมน์
