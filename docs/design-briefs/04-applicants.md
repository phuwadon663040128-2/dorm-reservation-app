# 04 — ผู้สมัคร (`/staff/applicants`)

> ต้องอ่าน `00-design-system.md` ก่อน · ออกแบบ 3 แนวทาง A/B/C ตามนิยามในไฟล์นั้น

## จอนี้คืออะไร

รายชื่อบัญชีผู้สมัครทั้งหมด เจ้าหน้าที่ใช้ค้นหาคนเพื่อดูว่าโปรไฟล์ครบไหม ผูก SSO หรือยัง
และ (ในอนาคต) อยู่ขั้นไหนของกระบวนการ

**ปัจจุบันจอนี้บางที่สุดในระบบ — มีแค่ค้นหา + ตาราง 5 คอลัมน์ ไม่มี action ใด ๆ**

## ข้อมูลที่ควรมีแต่ยังไม่ได้แสดง (ออกแบบเผื่อ)

จอนี้ควรเป็นจุดตั้งต้นของการตามหาคน ๆ หนึ่งในระบบ ควรเห็นได้จากที่นี่:
- อยู่ **กลุ่มรูมเมท** ไหน เป็นหัวหน้ากลุ่มหรือสมาชิก
- **จองห้องอะไรอยู่** สถานะ hold เป็นอย่างไร
- **ชำระเงินไปแล้วกี่รายการ จากทั้งหมดกี่รายการ**
- สถานะ **สัญญา** และ **กุญแจ**
- ประวัติกิจกรรมของคนนี้ (audit ที่กรองด้วย actor/related id)

## ปัญหาที่ต้องแก้

1. **ตารางนี้เป็นทางตัน** — ดูได้อย่างเดียว กดอะไรไม่ได้ ไปต่อไม่ได้
2. **ไม่มี filter เลย** มีแค่ค้นหา — กรองด้วย "โปรไฟล์ยังไม่ครบ" ไม่ได้
   ทั้งที่นั่นคือรายการที่เจ้าหน้าที่ต้องตามงาน
3. **สองคอลัมน์สุดท้ายเป็นสถานะเทคนิค** (โปรไฟล์/SSO) แต่สิ่งที่เจ้าหน้าที่อยากรู้จริง ๆ
   คือคนนี้ไปถึงขั้นไหนของกระบวนการจอง
4. ไม่มีการเรียงลำดับ

## โจทย์เฉพาะจอนี้

- **A (Console):** เพิ่ม filter chip (โปรไฟล์ครบ/ไม่ครบ, ผูก SSO/ไม่ผูก, มีการจอง/ไม่มี)
  + คอลัมน์ "ขั้นตอนปัจจุบัน" + คลิกแถวเปิด drawer โปรไฟล์เต็ม
  พร้อมทุกอย่างของคนนี้ (กลุ่ม/ห้อง/ชำระ/สัญญา/กุญแจ) ในที่เดียว
- **B (Workflow):** จัดผู้สมัครตาม **ขั้นที่อยู่** เป็นแท็บหรือคอลัมน์แบบ kanban —
  ยังไม่กรอกโปรไฟล์ → พร้อมจอง → ถือ hold อยู่ → รอชำระ → ชำระครบ → ทำสัญญาแล้ว → รับกุญแจแล้ว
  เห็นทันทีว่าคนตกค้างกองอยู่ขั้นไหน
- **C (Focus + Split):** ซ้ายรายชื่อค้นหาได้ ขวาเป็น **โปรไฟล์เต็มหน้าเดียวจบ**
  มี timeline กิจกรรมของคนนี้เรียงตามเวลา — ใช้ตอนนักศึกษาโทรมาถามว่า "ของหนูถึงไหนแล้ว"

## เงื่อนไขเพิ่ม

- ข้อมูลส่วนบุคคล — คำนึงถึง PDPA: อย่าแสดงเลขบัตร/ที่อยู่เต็มในตารางรวม
  ให้แสดงในหน้ารายละเอียดเท่านั้น และมี audit เมื่อเปิดดู
- อีเมลควรกดคัดลอกได้ (เจ้าหน้าที่ต้องติดต่อจริง)
- ถ้ามี action ให้เตรียมไว้: ส่งอีเมลแจ้งเตือน, ดูประวัติ audit ของคนนี้

## Store ที่เรียกใช้
