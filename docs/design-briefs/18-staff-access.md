# 18 — จัดการสิทธิ์เจ้าหน้าที่ (`/staff/access`)

> ต้องอ่าน `00-design-system.md` ก่อน · ออกแบบ 3 แนวทาง A/B/C ตามนิยามในไฟล์นั้น

## จอนี้คืออะไร

จอเฉพาะของ **ผู้ดูแลระบบ** (เมนูกลุ่ม "ผู้ดูแลระบบ" — `adminOnly`)

> **เจ้าหน้าที่ทุกคนมีบทบาทเดียวกัน** — ผู้ดูแลระบบเลือกได้ว่าแต่ละคนเข้าถึง**ส่วนงาน**ใดบ้าง
> การเปิด/ปิดสิทธิ์มีผลกับเมนูและ permission ในส่วนงานนั้น**ทันที**

โมเดล RBAC ของโปรเจกต์นี้คือ **single staff role + section access** ไม่ใช่ role หลายชั้น
ออกแบบให้สะท้อนโมเดลนี้ อย่าเผลอออกแบบเป็นระบบ role/permission matrix แบบทั่วไป

### ส่วนงานทั้งหมด (`StaffSection`)
| key | กลุ่มเมนูที่ควบคุม |
|---|---|
| `overview` | ภาพรวม (Dashboard, รอบรับสมัคร) |
| `reservation` | ห้องพักและการจอง (ห้อง, ผู้สมัคร, กลุ่ม, hold, จองแทน) |
| `payment` | การเงิน SCB (obligations, export, PDF, ผลชำระ) |
| `contract` | สัญญาและส่งต่อ (สัญญา, กุญแจ, ส่งมหาวิทยาลัย) |
| `system` | ระบบ (รายงาน, audit, ตั้งค่า) |

**หมายเหตุ:** Dashboard (`/staff`) เข้าได้เสมอแม้ไม่มีสิทธิ์ `overview`
แต่จะแสดงหน้า "ยังไม่ได้รับสิทธิ์เข้าถึงส่วนงาน" แทนตัวเลข

## ปัญหาที่ต้องแก้

1. **Switch เปลี่ยนสิทธิ์ทันทีโดยไม่มีการยืนยัน** — ทั้งที่ Alert เขียนไว้เองว่า
   "การเปลี่ยนสิทธิ์ทุกครั้งต้องบันทึก audit" การกดผิดหนึ่งครั้งคือตัดสิทธิ์คนออกจากงานทันที
   **ควรมี dialog ยืนยัน + เหตุผล อย่างน้อยสำหรับการ "ปิด" สิทธิ์**
2. **การ์ดต่อคนกินพื้นที่มาก** — 5 สวิตช์ต่อคน × เจ้าหน้าที่ 15 คน = เลื่อนยาวมาก
   และ**เทียบสิทธิ์ระหว่างคนไม่ได้เลย** ทั้งที่คำถามที่ถามบ่อยคือ "ใครดูแลการเงินบ้าง"
3. **ไม่มีค้นหา/กรอง** — หาเจ้าหน้าที่คนหนึ่งใน 15 คนต้องเลื่อนหา
4. **ไม่เห็นผลกระทบก่อนกด** — ปิดสิทธิ์ `payment` แล้วคนนั้นจะเข้าอะไรไม่ได้บ้าง ไม่มีบอก
5. **ไม่เห็นประวัติ** — ใครเคยมีสิทธิ์อะไร ถูกเปลี่ยนเมื่อไร โดยใคร ต้องไปดูที่จอ Audit
6. **ไม่มีการจัดการแบบกลุ่ม** — ตั้งสิทธิ์เจ้าหน้าที่ใหม่ 5 คนพร้อมกันต้องกด 25 ครั้ง
7. **ไม่บอกว่าตอนนี้มีใครกำลังใช้งานอยู่ไหม** — ตัดสิทธิ์ระหว่างที่เขาทำงานค้างจะเกิดอะไร

## โจทย์เฉพาะจอนี้

- **A (Console):** **ตาราง matrix** — แถว = เจ้าหน้าที่ คอลัมน์ = 5 ส่วนงาน ช่องเป็น checkbox/switch
  เห็นภาพรวมสิทธิ์ทั้งองค์กรในหน้าจอเดียว เทียบกันได้ทันที
  + ค้นหา + filter "มีสิทธิ์ส่วนงานนี้" + เลือกหลายคนเพื่อตั้งสิทธิ์พร้อมกัน
  + คลิกชื่อเปิด drawer ที่มีประวัติสิทธิ์ของคนนั้น
  **นี่น่าจะเป็นแนวทางที่ตรงกับปัญหาข้อ 2 ที่สุด**
- **B (Workflow):** จัดตาม **ส่วนงาน ไม่ใช่ตามคน** — 5 การ์ดส่วนงาน แต่ละใบแสดงว่าใครเข้าถึงได้บ้าง
  พร้อมปุ่มเพิ่ม/ถอดคน ตอบคำถาม "ใครดูแลการเงินบ้าง" ได้โดยตรง
  และมี flow "ตั้งค่าเจ้าหน้าที่ใหม่" เป็นขั้นตอน (เลือกคน → เลือกส่วนงาน → ตรวจทานผลกระทบ → ยืนยัน)
- **C (Focus + Split):** ซ้ายรายชื่อเจ้าหน้าที่พร้อมสรุปสิทธิ์ย่อ ขวาเป็นหน้าจัดการของคนที่เลือก:
  สวิตช์ 5 ส่วนงาน + **preview เมนูที่คนนี้จะเห็น** (แสดง sidebar จำลอง) + ประวัติการเปลี่ยนสิทธิ์
  — preview เมนูแก้ปัญหาข้อ 4 ได้ตรงที่สุด

## เงื่อนไขเพิ่ม

- **การปิดสิทธิ์ต้องมี dialog ยืนยันพร้อมเหตุผล** และบอกว่าคนนั้นจะเข้าอะไรไม่ได้บ้าง
  (การเปิดสิทธิ์อาจยืนยันเบากว่าได้ แต่ยังต้อง audit)
- ต้องมี **preview ว่าคนนั้นจะเห็นเมนูอะไรบ้าง** หลังเปลี่ยนสิทธิ์
- ต้องแสดง **ประวัติการเปลี่ยนสิทธิ์** (ใคร เปลี่ยนอะไร เมื่อไร เหตุผล) — เชื่อมกับ audit
- คนที่ยังไม่มีสิทธิ์ส่วนงานใดเลยต้องเด่นชัด — เป็นสภาพที่ทำให้เขาทำงานไม่ได้เลย
- **ห้ามให้ admin ตัดสิทธิ์ตัวเองจนล็อกตัวเองออก** — ออกแบบการป้องกันไว้
- Switch ต้องมี `aria-label` ครบเสมอ (มีอยู่แล้ว — คงไว้)
- จอนี้เป็น `adminOnly` — ต้องมีสภาพ "ไม่ใช่ผู้ดูแลระบบ" ด้วย
