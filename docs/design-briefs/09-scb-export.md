# 09 — SCB Export Batch / SLIPS (`/staff/scb/export`)

> ต้องอ่าน `00-design-system.md` ก่อน · ออกแบบ 3 แนวทาง A/B/C ตามนิยามในไฟล์นั้น

## จอนี้คืออะไร

สร้างและจัดการไฟล์ที่ส่งให้ธนาคาร SCB

> ไฟล์ `.xlsx` **ชีตชื่อ SLIPS** คอลัมน์ตามที่ธนาคารกำหนดเป๊ะ ๆ
> **ช่อง ID เว้นว่างเสมอ** · 1 แถว = ผู้พัก 1 คน × 1 action

จอนี้เป็นขั้นที่ 1 ของวงจรการเงิน: **Export → (ธนาคาร) → นำเข้า PDF → นำเข้าผลชำระ**

## ปัญหาที่ต้องแก้

1. **การ์ดแต่ละใบกางตาราง 9 คอลัมน์เต็ม ๆ** — batch เดียวมีร้อยแถว กางไว้หมดทุก batch
   จอนี้จะยาวเป็นกิโลเมตร ทั้งที่ส่วนใหญ่เจ้าหน้าที่แค่อยากรู้ว่า batch ไหนสถานะอะไร
2. **ไม่เห็นวงจรของ batch** — สถานะ 5 ค่านี้เป็นลำดับขั้นชัดเจน แต่แสดงเป็น badge เดี่ยว ๆ
   ไม่รู้ว่าติดอยู่ขั้นไหนมานานเท่าไร
3. **ปุ่มสำคัญที่สุด (สร้าง batch ใหม่) เป็นแค่ toast** — ยังไม่มีการออกแบบ flow เลย
   ทั้งที่ขั้นตอนคือ เลือก obligation → validate → preview → สร้างไฟล์
4. **ไม่มียอดรวมของ batch** — งานการเงินต้องกระทบยอดกับธนาคาร ต้องเห็นยอดรวมและจำนวนแถว
5. **checksum แสดงเป็นข้อความธรรมดา** — ควรคัดลอกได้และควรใช้ยืนยันว่าไฟล์ที่ดาวน์โหลดตรงกัน
6. ไม่มีตัวกรอง/ค้นหา batch

## โจทย์เฉพาะจอนี้

- **A (Console):** ตาราง batch ระดับบนสุด (id · สถานะ · จำนวนแถว · ยอดรวม · วันที่ · ผู้สร้าง · checksum)
  แถวเดียวจบต่อ batch คลิกแล้วกางแถวย่อยหรือเปิด drawer ที่มีตาราง SLIPS เต็ม
  · เลือกหลาย batch เพื่อดาวน์โหลดพร้อมกัน
- **B (Workflow):** จัดตาม **วงจรชีวิตของ batch** เป็นเลนหรือ stepper —
  ร่าง → ส่งออกแล้ว → รอ PDF → นำเข้าแล้ว → เสร็จ
  เห็นทันทีว่ามี batch ค้างอยู่ขั้นไหนกี่ใบและค้างมานานแค่ไหน
  พร้อมออกแบบ **flow "สร้าง batch ใหม่" เป็น wizard เต็ม**: เลือกรายการ → ตรวจ validation → preview ไฟล์ → ยืนยันสร้าง
- **C (Focus + Split):** ซ้ายรายการ batch ขวาเป็นรายละเอียด batch ที่เลือก —
  สรุปยอด + สถานะ + timeline การเปลี่ยนสถานะ + ตาราง SLIPS + ปุ่มดาวน์โหลด
  ไล่ดูหลาย batch ได้เร็วโดยไม่ต้องเลื่อนหนีจากรายการ

## เงื่อนไขเพิ่ม

- **ต้องออกแบบขั้น validation ให้ครบ** — ก่อนสร้างไฟล์ต้องแสดงว่าอะไรผ่าน อะไรไม่ผ่าน
  (เช่น ไม่มีอีเมล, ยอดเป็น 0, ชื่อยาวเกิน) และให้แก้หรือข้ามรายการนั้นได้
- **ต้องออกแบบขั้น preview ไฟล์** — เห็นว่าไฟล์ที่จะออกหน้าตายังไงก่อนสร้างจริง
- ตาราง 9 คอลัมน์กว้างเกินจอ → ต้องมีคำตอบเรื่อง horizontal scroll ที่ไม่ทำให้ทั้งหน้าเลื่อนตาม
  (`overflow-x: auto` ที่ตัวตารางเท่านั้น)
- **ห้ามเปลี่ยนชื่อหรือลำดับคอลัมน์ SLIPS** — เป็นข้อกำหนดของธนาคาร
  แต่ออกแบบให้ซ่อน/แสดงคอลัมน์รองในมุมมองบนจอได้ (ไฟล์จริงยังครบเหมือนเดิม)
- checksum ควรกดคัดลอกได้
- ต้องมีสภาพ **ไม่มีสิทธิ์** (`payment_export.create` ไม่ผ่าน)
