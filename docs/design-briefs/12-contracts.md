# 12 — สัญญา (`/staff/contracts`)

> ต้องอ่าน `00-design-system.md` ก่อน · ออกแบบ 3 แนวทาง A/B/C ตามนิยามในไฟล์นั้น

## จอนี้คืออะไร

จัดการสัญญาเช่าหอพัก — ตั้งแต่สร้าง พิมพ์ ให้ลงนาม รับกลับ จนถึงแนบสแกน

> **ห้องพักคู่ = 2 ฉบับใต้ 1 การจอง** (ลงนามแยกได้ แต่กลุ่มไม่สมบูรณ์จนกว่าจะครบ)
> **เหมาห้อง = 1 ฉบับ**
> **การพิมพ์ซ้ำ/แก้ไขต้องมีเหตุผลและเก็บฉบับเดิมไว้เสมอ**

### สถานะสัญญา (`ContractStatus`)
| ค่า | variant | ความหมาย |
|---|---|---|
| `not_generated` | outline | ยังไม่สร้าง |
| `ready_to_generate` | info | พร้อมสร้าง |
| `ready_to_print` | info | พร้อมพิมพ์ |
| `printed` | warning | พิมพ์แล้ว รอผู้พักลงนาม |
| `signed_received` | success | รับสัญญาลงนามแล้ว |
| `correction_required` | destructive | ต้องแก้ไข |
| `reprinted` | warning | พิมพ์ซ้ำ |
| `cancelled` | outline | ยกเลิก |

(label จาก `contractStatusLabel` ใน `@/lib/labels`)

### toast ปัจจุบัน
- รับสัญญา: "บันทึกรับสัญญาที่ลงนาม + แนบสแกน (private) ของ {ชื่อ} (เฟส P6)"
- พิมพ์ซ้ำ: "พิมพ์ซ้ำต้องกรอกเหตุผล และเก็บประวัติฉบับเดิม (CONTRACT-006)"

## กฎธุรกิจ

- **CONTRACT-006:** พิมพ์ซ้ำต้องกรอกเหตุผล และเก็บประวัติฉบับเดิมเสมอ ไม่ทับของเดิม
- ห้องพักคู่: 2 ฉบับใต้การจองเดียว — **ลงนามแยกได้ แต่กลุ่มไม่สมบูรณ์จนกว่าจะครบทั้งสอง**
- ไฟล์สแกนลายเซ็นเป็น **private เสมอ** (PDPA)
- สัญญาสร้างได้เมื่อการจองยืนยันถาวรแล้วและชำระครบ
- ต้องมีแม่แบบสัญญาแบบมีเวอร์ชัน (ตั้งค่าที่จอ Settings/Campaigns)

## ปัญหาที่ต้องแก้

1. **ความสัมพันธ์ "2 ฉบับใต้ 1 การจอง" หายไปหมด** — ตารางแบนราบเรียงตามคน
   ทั้งที่กฎสำคัญที่สุดคือ "กลุ่มไม่สมบูรณ์จนกว่าจะครบทั้งคู่"
   เจ้าหน้าที่ต้องไล่หาเองว่าอีกฉบับของห้องนี้อยู่ไหนและลงนามหรือยัง
2. **8 สถานะเรียงเป็น badge เดี่ยว** — ไม่เห็นว่าเป็นลำดับขั้นและตอนนี้ค้างอยู่ขั้นไหนนานแค่ไหน
3. **ไม่มี filter/ค้นหา/เรียง** — หาสัญญาของคนหรือห้องหนึ่งไม่ได้
4. **ไม่มีปุ่มสร้าง/พิมพ์** — มีแค่ "รับสัญญา" กับ "พิมพ์ซ้ำ"
   ทั้งที่สถานะ `ready_to_generate` และ `ready_to_print` ต้องมีปุ่มของมัน
5. **ไม่มี bulk action** — พิมพ์สัญญาทั้งชั้นหรือทั้งรอบต้องกดทีละใบ
   ทั้งที่งานจริงคือพิมพ์ทีเดียวหลายสิบใบ
6. **ปุ่ม "พิมพ์ซ้ำ" แสดงทุกแถวแม้สถานะ `not_generated`** — พิมพ์ซ้ำสิ่งที่ยังไม่เคยพิมพ์ไม่ได้
7. ไม่เห็นประวัติเวอร์ชันของสัญญาที่ถูกพิมพ์ซ้ำ/แก้ไข

## โจทย์เฉพาะจอนี้

- **A (Console):** ตารางหนาแน่น + filter สถานะ/ห้อง/รูปแบบ + ค้นหา
  · คอลัมน์ "คู่สัญญา" ที่บอกว่าห้องนี้มีกี่ฉบับ ลงนามแล้วกี่ฉบับ (เช่น "1/2")
  · เลือกหลายแถว → bulk พิมพ์ / bulk รับสัญญา
  · คลิกแถวเปิด drawer ที่มีประวัติเวอร์ชันทั้งหมดของสัญญาฉบับนั้น
- **B (Workflow):** จัดตาม **ขั้นของสัญญา** เป็นเลน — รอสร้าง → รอพิมพ์ → พิมพ์แล้วรอลงนาม → รับแล้ว → ต้องแก้ไข
  แต่ละเลนมีจำนวนและปุ่มจัดการแบบกลุ่มของขั้นนั้นโดยเฉพาะ
  ("พิมพ์ทั้งหมด 24 ฉบับในขั้นนี้") — ตรงกับวิธีทำงานจริงที่ทำทีละขั้นเป็นรอบ ๆ
- **C (Focus + Split):** **จัดกลุ่มตามการจอง ไม่ใช่ตามคน** — ซ้ายเป็นรายการ "ห้อง + การจอง"
  พร้อมตัวบ่งชี้ความครบ (1/2, 2/2) ขวาแสดงสัญญาทุกฉบับของการจองนั้นเรียงคู่กัน
  พร้อมประวัติเวอร์ชันและปุ่มจัดการรายฉบับ — แก้ปัญหาข้อ 1 ตรงที่สุด

## เงื่อนไขเพิ่ม

- **ปุ่มพิมพ์ซ้ำต้องมี dialog + เหตุผลบังคับ** + ข้อความยืนยันว่าฉบับเดิมจะถูกเก็บเป็นประวัติ
- **ปุ่มรับสัญญาต้องมีการอัปโหลดไฟล์สแกน** + ป้ายกำกับชัดเจนว่าไฟล์นี้เป็น private
- ปุ่มควรแสดงตามสถานะจริง ไม่ใช่แสดงทุกปุ่มทุกแถว
- ห้องพักคู่ที่ลงนามครบทั้ง 2 ฉบับควรมีสัญญาณ visual ที่ต่างจากที่ลงนามฉบับเดียว
- ต้องมีสภาพ **ไม่มีสิทธิ์** (`contract.generate` / `contract.receive`)
