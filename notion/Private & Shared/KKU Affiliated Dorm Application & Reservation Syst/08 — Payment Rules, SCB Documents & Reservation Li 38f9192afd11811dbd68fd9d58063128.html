08 — Payment Rules, SCB Documents & Reservation Lifecycle

Purpose

Last revised: 2026-07-10

This page defines resident pricing, payment actions, SCB Bill Payment document exchange, payment status, exact-room holds, and reservation confirmation.

The previous normal flow of shared static QR + applicant slip upload is superseded.

Core payment model

exact room and roommate group ready
→ create one resident obligation per payment action
→ finance reviews only overrides/exceptions
→ export SCB XLSX batch
→ SCB/internal software generates official QR payment-form PDF
→ import/match returned PDF pages
→ residents pay
→ import SCB result report or record manual bank reference
→ all required obligations complete
→ staff confirms reservation

Payment obligation ownership

Every payment obligation belongs to:

  • one resident;
  • one reservation group;
  • one exact room;
  • one academic year/payment cycle;
  • one payment action;
  • one pricing-rule version or approved override.

Ref.1 + Ref.2 is not a unique resident key. Roommates may share both references.

Occupancy payment rules

Shared room

  • Two separate residents.
  • Separate payment obligations for each resident.
  • Each resident normally pays their own obligations.
  • One shared room-group payment deadline.
  • Both residents’ required obligations must be complete before permanent confirmation.

Whole-room rental / เหมาห้อง

  • One resident.
  • One full-room obligation per payment action.
  • One contract.
  • A converted shared reservation recalculates and supersedes old obligations.

Payment actions

ROOM

Room-fee obligation. Current reference format example: ROOM2569.

HL

Happy Living / converted-air-room service obligation. Every HL room creates a separate HL obligation in addition to ROOM.

Student-facing UX may describe the room simply as air-conditioned, but backend/accounting must preserve the split.

Additional actions

The domain model must support future codes, deposits, installment cycles, and other fees without schema changes.

Pricing

Pricing may depend on:

  • exact room;
  • room configuration;
  • occupancy mode;
  • applicant type;
  • academic year/cycle;
  • payment action;
  • active pricing-rule version.

Normal rows are calculated automatically.

A finance/payment administrator may override one current obligation. The override:

  • requires a mandatory reason;
  • creates an audit event;
  • affects only the current obligation/export row;
  • does not silently change permanent pricing rules.

Permanent pricing changes use a separate permission and versioned rule update.

SCB export contract

One row equals:

one resident × one payment action

Current mapping:

  • ID — blank;
  • Payer Name * — payment description/title;
  • Ref.1 * — exact room number;
  • Ref.2 — action + Buddhist academic year;
  • Amount * — numeric amount;
  • Payment Date * — bill issue date;
  • Email Address — supplied because internal software requires it;
  • Alert Message — DEFAULT;
  • Remark — optional/configurable.

All rows may be exported in one batch under the current baseline, while batch grouping remains configurable.

Payment-document lifecycle

Not Generated
→ Ready for Export
→ Exported to SCB Batch
→ Awaiting Returned PDF
→ Payment Form Ready
→ Superseded / Cancelled where needed

Returned PDF behavior:

  • one combined multipage PDF;
  • original file stored privately;
  • pages matched to resident obligations using resident-specific page text;
  • page order and assumed descending room number are not identity;
  • ambiguous pages require authorized manual review;
  • replacement preserves the old version.

Payment-result lifecycle

Awaiting Payment
→ Result Imported / Manual Reference Recorded
→ Paid / Unpaid / Exception
→ Confirmed / Cancelled / Refund Status

Exception categories:

  • underpayment;
  • overpayment;
  • duplicate transaction;
  • late payment;
  • payment after hold expiry;
  • result row cannot be matched;
  • ROOM paid but HL unpaid;
  • one roommate paid while the other remains unpaid.

Exceptions enter staff review rather than silently confirming or rejecting the room.

Manual payment

Authorized staff may record a manual payment only with:

  • bank transaction/reference;
  • mandatory staff note;
  • actor and timestamp;
  • reason/evidence reference;
  • audit event.

Room holds and payment timing

15-minute roommate confirmation hold

Leader reservation holds the exact room immediately. When required by campaign setting, the roommate must confirm the selected room within 15 minutes or the room releases immediately.

72-hour payment hold

After the group is ready, the exact room remains held for 72 hours under the current baseline.

Public UI shows Temporarily Held and expiry time.

If one roommate pays and the other does not, keep the group pending until the shared deadline, then release/cancel under the provisional rule and send the paid obligation to manual/refund resolution.

Reservation lifecycle

None
→ Held for Roommate Confirmation
→ Held for Payment
→ Confirmed / Released / Expired / Cancelled

Current provisional confirmation rule:

all required ROOM/HL obligations paid
+ authorized staff confirmation
→ exact room Confirmed

Physical contract signing follows confirmation and is tracked separately.

Refunds

The application records:

  • requested;
  • approved/rejected;
  • recipient/entity responsible;
  • amount;
  • external reference;
  • completed date;
  • notes.

Actual refund execution remains outside the MVP. ROOM and HL may require separate external processes.

Renewal and replacement effects

  • Renewal creates new-cycle obligations using reused resident/room data.
  • Roommate replacement supersedes old obligations and creates new ones.
  • Shared-to-whole-room conversion supersedes old shared obligations.
  • Historical payment forms/results are never overwritten.
  • Changes after university handoff generate correction records/exports.

Core statuses shown to applicants

Display payment actions separately:

ROOM2569: Payment Form Ready / Paid / Exception
HL2569: Payment Form Ready / Paid / Exception

Also show:

  • shared group deadline;
  • exact-room hold expiry;

  • reservation confirmation;
  • replacement/cancellation instructions.

Staff reports

  • obligations ready for export;
  • SCB export batch status;
  • returned PDF unmatched pages;
  • paid/unpaid obligations;
  • group payment completion;
  • payment exceptions;
  • manual payment records;
  • superseded/cancelled bills;
  • refund status;
  • confirmed rooms awaiting contracts;
  • confirmed residents awaiting university handoff.
